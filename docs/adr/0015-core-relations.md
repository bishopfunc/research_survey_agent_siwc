# ADR 0015: 関係は親子・系統・論文・主張と根拠に絞り、古い型は読めるが書かない

状態: Accepted
日付: 2026-10-12 JST
関連design doc: [0022](../design/0022-timeline-trees.md)、[DSL調整ガイド](../dsl-schema.md)

## 背景

ユーザー指示（2026-10-12）：詳細画面のグラフ（つながり図）は見づらいので出さない。それに応じて余分なDSLを変えてよい。手法・課題・論文の親子と、主張・根拠は残す。

つながり図は、depends_on・related_to・caused_by・tradeoff_with・assumes・refines・introduces_issue などの多様な関係と、ナレッジの参照（papers・related）を同じ図に描いていた。画面の主な見方は課題ツリー・手法ツリー・論文ツリーに移っており、これらの関係はツリーにも採点にも使っていない。

## 判断

- 残す関係（`CORE_RELATION_TYPES`）：part_of・specializes（課題・手法の親子）、extends・builds_on（手法の派生）、instance_of（系統）、proposes・addresses（論文と手法・課題、手法と課題）、about・supports・contradicts（主張と根拠）。
- 詳細欄の「関連」はこれらと論文の claims・evidence だけを並べる。つながり図・編集フォーム・選択解除の×は外す。
- Codexにはこれらの型だけを使わせる（Promptの関係の一覧を残す型だけにし、他分野の考え方は課題に対応する手法として `addresses` でつなぐ）。
- スキーマと検証は古い型も受け付けたままにする。保存済みの調査は壊れず、古い関係は保存されたまま表示されない。

## 代替案

- スキーマから古い型を消す：保存済みの調査とCodexの過去の変更案が検証に落ちるため、移行（古い関係の削除か変換）が要る。古い型を受け付けるコストは小さいので、今は消さない。古い型が保存データから無くなった時点で見直す。
- つながり図を残して見やすくする：ユーザーが見づらいとして外す判断をした。

## 影響

- ナレッジと論文・課題のつながり（Keywordのpapers・related）は関連の一覧に出ない。論文の詳細の「使われるナレッジ」とナレッジタブで見る。
- 手法が生む課題（introduces_issue）は新しく作られない。必要になれば、課題の親子か手法と課題の関係で表す方法を検討する。
- 修正はチャットからCodexに頼む（編集フォームが無くなったため）。
