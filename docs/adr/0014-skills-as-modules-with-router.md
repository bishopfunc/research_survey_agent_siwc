# ADR 0014: 調査の手順はTSのスキルモジュールにし、追加の依頼は短い判定で振り分ける

状態: Accepted
日付: 2026-10-12 JST
関連design doc: [0023](../design/0023-skills-and-routing.md)

## 背景

ユーザー指示で、複数ステップのPromptをスキルとして管理し、追加の依頼を深掘り・違う視点・解説などに動的に振り分ける。解説は調査を変えないので、Codexの出力の形式（output schema）が変更案と違う。output schemaは `codex exec` の起動時に決まるため、Codexを動かす前にスキルが決まっている必要がある。Agentは引き続きChatGPTプランのCodex（`codex exec`）で、APIキー方式に置き換えない。

## 判断

- スキルは `packages/agent/src/skills/` のTypeScriptモジュールで定義する（1スキル1ファイル、型 `Skill`）。版・使う場面・手順・出力の種類を持ち、Lab・サーバー・試験が同じ定義を読む。
- 空の調査は判定せず新規調査のスキル。中身のある調査では、Web検索なしの短いCodexの実行でスキルを1つ選び（output schemaで `{ skill, reason }`）、選んだスキルの指示と出力の形式で本番の実行をする。判定に失敗したら語句による判定で続ける。

## 代替案

- Codexの組み込みのスキル（SKILL.mdをCodexが読み、Codex自身が選ぶ）：研究用のCodexはユーザー設定とプロジェクトの指示を読まない設定で動かしており（設定の継承とローカルファイルの読み取りを避けるため）、スキルのファイルを読ませるには作業ディレクトリへの配置が要る。何よりoutput schemaが起動時に固定されるため、解説と変更案を同じ実行で切り替えられない。見送り。
- 1回の実行で、Codexにスキルを選ばせ、出力を「変更案か解説」のどちらかを持つ形にする：判定の待ち時間は無いが、どのスキルでも全スキルの指示を渡すのでPromptが長くなり、上限時間やWeb検索の要否をスキルごとに変えられない。見送り。
- 語句による判定だけ：速いが、「詳しく」のように深掘りと解説の両方に使う語で誤る。判定の失敗時の代わりとしてだけ使う。
- SKILL.md形式のMarkdownファイルで管理：編集しやすいが、Cloudflare Workerへの同梱にテキストモジュールの設定が要り、型の検査ができない。将来、スキルを利用者が編集する段階で見直す。

## 影響

- 追加の依頼は判定の分（Codexの起動と短い応答、数秒〜数十秒）だけ遅くなる。
- スキルを足すときは、モジュールを1つ足し、一覧と判定の候補に入れ、Labと試験を更新する。
- 判定の誤りは、経過に出る理由で利用者が気づけるようにする。誤りが多ければ、判定の説明か語句の判定を見直す。

## 根拠

- `codex exec --output-schema` は実行ごとに1つのschemaを受け取る（既存のPoCの実装 `scripts/poc-server.ts`）。
- 研究用のCodexは `--ignore-user-config`・`project_doc_max_bytes=0` で動かしている（[0012](../design/0012-codex-research-modes.md)）。
