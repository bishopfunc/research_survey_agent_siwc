## 目的と範囲

ユーザー指示（2026-10-14）：「チュートリアルの作成や研究手法の分類は以下の記事を参考にして」（[ナビゲーションにおける地図表現の研究動向](https://zenn.dev/epicai_techblog/articles/bfe50e2e0ad8ec)、2026-08-10）。続けて「MAPF見本 / LLM Open Challenge / 地図表現 全部を統合して」。

3つの手本と、そこから取るもの：

| 手本 | 取るもの |
|---|---|
| MAPF見本（アプリのサンプル、[kei18のMAPF入門](https://kei18.github.io/note/posts/mapf-tutorial/)に倣った） | 記法と数式による問題設定、素朴な方法から最新まで「前の方法の限界→考え方→保証→規模」、まとめと選び方、派生問題、手を動かす、さらに学ぶ |
| [LLM research open challenges](https://huyenchip.com/2023/08/16/llm-research-open-challenges.html) | 課題と達成度（課題ごとに1節。なぜ重要か、達成度の主張、論文2本以上、解決の度合い、未解決の問い） |
| 地図表現の研究動向 | はじめにで扱うこと・扱わないこと・前提・対象読者、言葉による定義と構成要素、典型的な設定での構成要素ごとの手法と各手法の役割・入力→出力、中心の軸に沿った研究動向「AからBへ」と代表論文の名前（年）、まとめの役割の整理と今後の方向性3つ、複数の軸による手法の分類 |

Tutorialの役割の種類と関係の型は変えない。分類の軸だけDSLに足す（下の「手法の分類」）。

## 章立て

役割の順は `motivation → definition → methods → summary → challenges → variants → hands_on → further_reading → conclusion`（はじめにを先頭へ移した。以前は問題設定が先頭）。

1. はじめに（motivation）：扱うこと・扱わないこと・前提・対象読者を「- 」の箇条書きで、続けてなぜ面白い問題か・応用を出典2つ以上で。
2. 〇〇とは（definition）：言葉で定義し、構成要素（部分問題・処理の要素）を箇条書きで挙げる。記法と数式で書ける分野は、記法と単独行の数式で定義する。出典つき。
3. 典型的な〇〇（methods の最初の節）：典型的な設定を1つに決め、構成要素ごとの典型的な手法を「- 要素：手法（年）[@論文]」で挙げ、各手法を役割と入力→出力で説明する。素朴な方法とその限界もここで述べる。
4. 研究動向（methods の2節目以降、見出しは「研究動向：AからBへ（手法）」）：分野の中心の軸（地図表現の記事では地図）に沿って、1節に1つの変化。前の方法の限界から始め、新しい考え方・保証・規模、代表論文を「名前（年）[@論文]」で、論文の図とともに。最後の節は最新の研究。
5. まとめと選び方（summary）：どの場面でどの手法か（出典つき）、中心の概念がこれまで担ってきた役割の整理、今後の方向性を3つ以上「- 」の箇条書きで。
6. 課題と達成度（challenges）：LLM Open Challengesの形（従来どおり）。
7. 派生問題とタスクの変遷（variants）：派生問題・タスクの変化1つに1節、出典つき（違い・難しくなる点・対応する手法）。
8. 手を動かす、さらに学ぶ、おわりに。

本文は表を描けない（[0018](0018-tutorial.md) の描画は段落・箇条書き・`###` 見出し・数式・引用）ので、要素と手法の対応は表でなく「- 要素：手法」の箇条書きにする。

目次では、同じ役割が続く節のうち見出しが「接頭辞：残り」の形で接頭辞が共通する節を1つの章（題は接頭辞、節の題は残り）にまとめる（例：3 研究動向 → 3.1 最適から有界準最適へ（ECBS））。

## 手法の分類（共通ルール methods）

系統（Concept）は考え方で名付ける従来の規則に、地図表現の記事の分類を足す：

- まず分野のサーベイに倣って分類の軸を決める（処理の中の役割＝機能、何を表すか＝表現、どう推定・学習するか＝方式、何を入力とするか＝入力）。
- 分野の歴史で最も大きく変わった軸を中心の軸として1つ選び（地図表現の記事では地図）、系統をその軸に沿って古典から最新へ並べる。
- 系統の説明（description）に、どの軸の系統か（「軸：…」）と、前の系統のどの限界に答えたか（AからBへ）を書く。
- 系統の中の手法は従来どおり時系列に、派生関係（extends・builds_on）を入れる。

軸はDSLの項目として持つ（ユーザー指示「手法の分類の軸を構造（DSLの項目）として持つ」、[ADR 0026](../adr/0026-classification-axes.md)）：

- 分野（Domain）の `classification_axes`：軸ごとに `id`・`label`・`kind`（function・representation・approach・input・other）・`description`・`central`（調査に多くとも1つ）。分野ごとに最大6つ。
- 系統（Concept）の `axis`：軸のID。
- 検証：軸のIDの調査全体での重複、中心の軸が2つ以上、存在しない軸を指す系統（誤りに分野のIDも書く）を拒む。
- Fill：軸の抜けは1つの組にまとめ、その組には分野とすべての系統の変更を許す。Exploreは既にある軸のIDだけを使い、存在しない軸の系統は外す。
- 点検（`assessSurvey` の `axes`）：系統がある調査では、軸があり、中心の軸が1つで、すべての系統が軸を持つ。`findGaps` は軸の無い系統と、軸の無い分野を抜けとして挙げる。
- 画面：手法ツリーは中心の軸の系統から並べ（軸の順は分野の一覧の順、同じ軸の中は最も古い手法の年の順）、行の見出しに軸の名前を出す。分野と系統の詳細に軸を表示する。
- サンプル：MAPFの分野に中心の軸「計画の方式」（approach）を置き、3つの系統（衝突を分岐して解く探索、優先度で決める準最適解法、学習ベース）をその軸の系統にする。

系統の説明には、引き続き前の系統のどの限界に答えたか（AからBへ）を書く。研究動向の節はこの中心の軸の系統に沿う。
