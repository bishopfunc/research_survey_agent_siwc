# 0007: 分野の入口から始めるサーベイPrompt

状態: Implemented（Prompt定義・Lab表示。2026-10-12から新規調査としてCodexのWeb検索に接続、[0012](0012-codex-research-modes.md)）
日付: 2026-10-12 JST
対象タスク: P07

サーベイは個別論文の検索からではなく、その分野の情報源の把握から始める。

1. 分野・隣接分野・対象期間を定め、代表的な学会を調べる。正式名、略称、公式URL、扱う話題、選定理由を残す。必要に応じて関連ジャーナル・ワークショップも区別する。
2. 分野の既存ソースを並行して調べる（2026-10-12のユーザー指示で並列化。同日、ブログ・記事を2cとして追加、[0013](0013-keywords-and-field-sources.md)）。
   - 2a. 代表的なサーベイ論文・レビュー論文を探す。タイトル、出版年、著者、出典、対象範囲、分類軸、参考文献を確認する。古典的な整理と最近の整理を照合する。
   - 2b. awesome-xxxxなどの文献・コード集を探す。URL、対象範囲、更新状況、分類を確認し、論文・実装を発見する入口として使う。star数だけで代表性を判断しない。
   - 2c. 研究室・学会・企業の技術ブログ、チュートリアル、解説記事で用語と研究の流れをつかむ。URL・著者または組織・公開日を残し、主張の根拠には使わない。
3. 2a〜2cの結果を突き合わせてから一次論文をたどる。読んだ論文から初心者向けのキーワードも作る。[論文ライブラリ](0010-paper-library.md)にある論文はPDF・本文を読み直さず保存済みの内容を使う。課題・手法・系譜・未解決点を整理し、各主張を元論文の条件と根拠で確認する。コード公開状況と代表Figの候補も記録する。

`packages/agent/src/research-prompt.ts` に調査用Promptと日本語の段階説明を共有定義する。テーマと調査基準日をデータとして渡し、文献・リポジトリ内の指示には従わない。調査できない場合は未確認を残し、学会・文献・URL・引用数・Figを捏造しない。利用したソース（論文、アブストラクト、サーベイ、READMEの記述、学会ページ）は、原文の該当箇所をリンク・位置・取得日と一緒に残し、記憶から引用やアブストラクトを作らない。

2026-10-12：`survey-discovery/3` で新規調査の指示（`survey-new/1`）に組み込み、結果を文章ではなくPatchで返すようにした。追加調査は別の指示（`survey-additional/1`）にする。

`/lab` は調査用Promptと現在実行中の編集Promptを区別して表示する。現在のCodex編集PoCは外部検索を行わないため、今回の調査Promptは定義とレビューまで実装し、実調査への接続は後続のDiscoverer/Workflowで行う。実行時と共通という表示は編集Promptだけに適用する。

検証：調査段階の順序と2a・2bの並行、ライブラリ照合と原文・リンクの規則、Promptのテーマ・基準日への受け渡し、Labの表示と未接続の明示、既存編集Promptの維持、必須checkとWorker dry-runを確認する。

## 2026-10-12: 一般Web検索から始める

新規調査の第1段階は、分野名とsurvey・review・awesome・tutorial・overviewなどを組み合わせた一般Web検索から始める。最初の検索群ではsite指定、URL指定、既知の個別論文名による限定を行わない。検索で見つけたサーベイ・awesome・学会・ブログ・チュートリアルを開き、情報源と分野の全体像（課題・手法の系統・評価の慣習）をURL付きで整理した後、特定サイトや一次論文に絞る。実行PromptとLabの第1段階の説明を同期する。これはPromptの指示であり、段階の通過をアプリが強制する実装は含まない。
