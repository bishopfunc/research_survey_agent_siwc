# 0009: ResearchRabbit風の探索UI

状態: Implemented
日付: 2026-10-12 JST
対象タスク: P09
関連: [UI/DSL PoC](0002-ui-dsl-codex-poc.md)、[Lab](0004-review-lab.md)、[design.md](../../design.md)。[0008 Distill風](0008-distill-reading-ui.md)を置き換える。

## 目的と範囲

ユーザー指示により、[ResearchRabbit](https://www.researchrabbit.ai/)を参考に、論文と課題のつながりをたどる探索型の画面へ変える。調査データ、4つの表示、編集、Codex、履歴、Fork、Fig抽出、Labのルートと責務は変えない。同じ指示で、画面上の説明文（使い方・読み方の解説、キャッチコピー、補足の注記）を可能な限り削る。この方針はAGENTS.mdにも記録した。

原サイトのロゴ、文章、画像、配色の値そのものは使わない。公開ページのCSSから読み取った特徴（白とパステル、Plus Jakarta Sans、丸いカード、ピル型ボタン、青の主操作）を、既存のtokensで再構成する。

## 現状と変更

| ResearchRabbitの要素 | このアプリでの対応 |
| --- | --- |
| 色分けしたコレクション | 左の「コレクション」に調査（branch）を色付きで並べる（2026-10-12：課題の階層は削除） |
| 上部の探索の履歴 | 上部の時計アイコンのプルダウンに版（Commit）を新しい順に、JSTの日時で並べる。選ぶと過去版を表示する。右端にサンプル・新規調査・フォーク。Agentのcheckpointとは別物 |
| 引用ネットワーク | 右の詳細に、選択項目と直接つながる項目の図を置く。点を選ぶとその項目へ移動する |
| モードの切替 | 課題・手法・課題と手法・論文をピル型のタブで切り替える |
| 論文の一覧 | 白い丸角カードにタイトル・著者・年・会議・一言概要・引用数・コード・主張/根拠数を表示 |

つながり図は `packages/domain/src/connections.ts` の `buildConnections` で作る。Paperの `proposes / addresses / claims / evidence` 配列と型付き関係を、両方向に、重複なく一つの近傍にまとめる。存在しないIDは表示しない。図は最大12件で、超えた分は件数だけ示し、下の「関連」一覧に全件を出す。矢印は関係の向き（from→to）。双方向の関係は矢印を付けない。種類ごとの色は課題=ピーチ、手法=ターコイズ、論文=ラベンダー、主張=緑、根拠=黄、分野=空色。色だけに頼らず、凡例・ラベル・読み上げ名で種類を示す。

手法の詳細にあった「提案・関連論文」は「関連」一覧に統合した（同じ論文を「提案した論文・年」として表示）。論文の出版種別は英語の内部値でなく日本語で表示する。

削った説明文：見出しの説明、ビューごとの説明、比較表の読み方、セル選択の案内、系譜の脚注と凡例の注記、Codexの手順タグと補足、フッター、Fig抽出の導入文、空状態の長い案内。未検証のサンプル・過去の版・base競合・エラーは、短いラベルか一文で残す。比較表の読み方は読み上げ用captionだけに残す。

2026-10-12追記（ユーザー指示）：版の表示を「v1・v2」からタイムスタンプに変えた。左の課題一覧を削除し、「新しい調査」を「新規調査」に改名し、右上にサンプル・新規調査・フォークの順で並べた。新規調査ボタンは空の調査を作り、Codexの入力欄へ移る（新規調査・追加調査の切替は画面に置かない）。コレクションの一覧は縦いっぱいに広げた。課題タブに課題の種類（本質的課題・部分課題・手法依存）の絞り込みを付け、何も選んでいないときは右側に課題ツリーを出す（詳細の×で選択を解除）。課題タブの「＋課題」「＋手法」ボタンは削除した。検索欄を削除し、全タブで「中央にコンテンツ、右に詳細タブとチャットタブのパネル（下に入力欄）」に統一した。チャットには、この調査でのCodexへの依頼と保存した結果の履歴、実行中の経過、差分の確認・保存を出す。コレクションは削除できる（最後の1つは不可。削除後に「元に戻す」）。左のコレクション欄と右のパネルは、それぞれ細いアイコンの列に折りたためる（状態はこのブラウザに保存）。右パネルは上のバーの下から画面下端までの全高で、背景は白、区切りは左の1本の線だけにした（浮いたカードはやめた）。課題タブの「＋課題」「＋手法」に続き、キーワードの「＋キーワード」「論文から抽出」も削除した。タイトル下の件数・状態のチップを削除した（件数はタブ、由来は詳細欄、過去の版は履歴で示す）。変更案の受け入れ表示が長かったため（実例で87件の操作と約600字の要約が全部開いていた）、チャットの変更案は「要約3行（押すと全文）」「N件の変更」「破棄」「保存」だけを最初に出す形にした。一覧は開くと種類別（分野・課題・手法・論文・主張・根拠・キーワード・関連・調査名）の見出しになり、見出しを開くと1行ずつの項目、項目を開くと内容（変更・削除は変更前後）を出す。関連は「A → B」と関係の種類を並べる。操作行は一覧をスクロールしても上に残る。破棄は通知の「元に戻す」で戻せる。経過は変更案の上に1行で出し、検索回数はサーバーの集計を使う。

## 契約とデータ

DSL、保存形式、API、Patch、Commitは変更しない。`buildConnections` は表示用の純粋関数で、snapshotを変更しない。色とfont-familyは `tokens.css` のトークンだけを参照する。フォントは `@fontsource/plus-jakarta-sans` と `@fontsource/ibm-plex-sans` をローカル配信し、外部CDNへ問い合わせない。0008で導入したNewsreaderは削除した。

## 失敗と競合

過去版では編集・Codex実行を無効にし、Forkか最新へ戻る操作を出す。base不一致の変更案は適用しない。つながり図の対象が見つからない場合は図を出さない。

## 検証と完了条件

- `buildConnections` の両方向・重複排除・Claim/Evidence・参照切れ・未知IDを単体試験する。
- 1440/1024/768/414/375/320pxで、横溢れがないこと、タブ・検索・関連図ラベルが欠けないことを確認する。図と比較表だけが領域内で横スクロールしてよい。
- 4つの表示、詳細、関連図からの移動、Lab、必須checkとWorker dry-runを確認する。実Codex推論はデザイン変更の対象外。

## 未解決事項
