# 0026: 概要・解説・図解と出典の徹底

関連: [0025 事実と出典](0025-facts-and-sources.md)、[0016 論文の重要な図](0016-paper-key-figures.md)、[ADR 0017](../adr/0017-evidence-as-common-source.md)

## 目的と範囲

ユーザー指示（2026-10-12）：

- 「主張と根拠」は「主張」にする（主張の出典は付けたまま）。「貢献」は独立した区分、「関連」も他の区分と同じ階層にする。
- どんなもの？をはじめ、論文の要点のすべてに出典を付ける。
- 詳細画面に戻るボタンを付ける。
- 「理解に重要なFig」は図に限らず、図・表・アルゴリズム・数式のすべてに出典を付ける。名前は「図解」。論文の良い節も取り出す。
- 「最新を取得」：arXivの図解と引用数を取り直す。アイコンと表記は「引用数を更新」と同じ作り。
- 論文の「概要」は「解説」にする。「概要」は課題・手法・論文・ナレッジ・文献ガイド・チュートリアルに共通の概念で、その項目を一言で説明する。
- 「アブストラクト」は「要旨」と呼び、解説と並ぶ区分にする。
- 課題ツリー・手法ツリーの項目に概要を出し、論文ツリーと同じ大きさにする。親の課題・手法（行見出し）にも概要を出す。課題には達成度と解決度合いを出す。
- 手法は同じアプローチの群の総称。ある手法が発端の群なら「〜系」はよいが、論文名をそのまま手法名にしない（Promptに追加）。
- 新規調査の題は、チャット欄の入力に合わせて変わる。コレクションに実行中・完了などの状態を出す。
- 出典の表示が詰まっていて見にくいので改める。
- SOTAはSoTAと書く。ナレッジの「モデル」を「学習済みモデル」と「アーキテクチャ」に分ける。

## 概要（共通）

概要＝その項目を一言で説明する一文。新しい項目は作らず、既存の一文の項目を概要として扱う（保存済みの調査を変換せずに済むため）。

| 型 | 概要の項目 | 概要の出典 |
|---|---|---|
| 論文 | `one_line_summary` | `reading.cites.summary` |
| 課題・手法・系統・領域 | `description` | `evidence` |
| ナレッジ | `meaning` | `evidence` |
| 文献ガイド | `summary` | その文献自体（URL） |
| チュートリアル | `summary`（新規・任意） | 本文の引用 |

ドメインの `overviewOf(entity)` と `overviewSources(entity)` が対応を一か所に持つ。Promptは「概要は一文」と定める。

## DSL

- `Reading.cites`（任意）：要点の項目ごとの出典。`summary`（概要＝どんなもの？）・`contributions`・`novelty`・`key_idea`・`validation`・`discussion` の各キーに出典（Evidence）のIDの配列。検証はEvidenceを指すこと。従来の `reading.evidence` は全体の出典として残す。
- `Reading.key_sections`（任意）：理解に重要な節。「3.2 Pseudocode: 理由」の形で、先頭の節番号でarXiv HTMLの節と照合する。
- `Tutorial.summary`（任意）：チュートリアルの概要（一文）。
- ナレッジの分類に `architecture`（アーキテクチャ：モデルの構造や部品の型）を足す。既存の `model` は「学習済みモデル」（重みが公開・配布された特定のモデル）と表示する。保存済みの `model` はそのまま有効。

## arXivの取り出し

- 図・表・アルゴリズム・数式に `anchor`（HTMLの要素ID）を足し、出典リンクを `source_url#anchor` にする。
- 節（`ltx_section`・`ltx_subsection`）を取り出す：番号・題・anchor・本文の先頭（段落のみ、最大1200字）。参考文献と謝辞は除く。
- 解析器の版を6に上げ、保存済みの結果を取り直す。
- 「この論文を更新」のarXivの部分は保存済みの結果を使わずに取り直す（`POST /api/arxiv-figures/:id?refresh=1`）。arXivへの間隔と再試行は従来どおり。

## 画面

論文詳細の区分（すべて同じ階層）：

1. 概要：一言の説明と出典
2. 要旨：アブストラクト（和訳と原文、開いたまま）
3. 解説：先行研究との差・キモ・検証・議論（各項目に出典）、重要な節（arXivの節。原文の先頭と出典リンク）
4. 貢献：貢献の一覧と出典
5. 図解：図・表・アルゴリズム・数式（各項目に出典リンク）、代表Fig
6. 主張：主張（状態・条件・時点）とその出典
7. 事実と出典
8. 関連
9. メタ情報

- 課題・手法・系統・ナレッジ・文献ガイドの詳細も先頭に「概要」（一文と出典）を置き、関連を同じ階層の区分にする。チュートリアルは題の下に概要を置く。
- 重要な節：`reading.key_sections` に挙がった節。無い場合は題から手法を説明する節（Method・Approach・Algorithm など）を最大2つ選ぶ。
- 戻る：詳細で項目を選ぶたびに直前の項目を履歴に積み、詳細の上部の戻るボタンで1つ戻る。調査を切り替えると履歴を消す。
- 出典：1件ごとに枠で区切り、上の行に出典元と位置、その下に原文の先頭2行を出す。開くと原文の全体と、出典元・出典の詳細・リンクを出す。
- ツリー：課題ツリー・手法ツリーの項目は論文ツリーと同じ大きさのカードで、名前・英語の専門用語・概要を出す。課題の項目には達成度（解決度合いのラベルと主張、無ければ未調査）を足すため一回り大きくする。行見出しの親（根の課題・系統・論文ツリーの課題と手法）にも概要を出し、課題には解決度合いのラベルを出す。
- 手法名：サンプルの手法を「衝突ベース探索（CBS系）」「制約を遅延して加える配置探索（LaCAM系）」のようなアプローチの群の名前にし、英語の専門用語の先頭をアプローチの用語にする。
- 新規調査の題：題が「新規調査」のままの空の調査は、チャット欄に入力中または実行中の依頼の1行目（40字まで）を見出しとコレクション名に出す（保存はしない）。研究が題を付けずに保存されたら依頼を題にする。
- コレクションの状態：名前の横に、そのコレクションの調査の実行状態（実行中・完了・失敗・取消）を短いラベルで出す。開いていないコレクションの実行は4秒ごとに状態を問い合わせる（実行中の間だけ）。
- この論文を更新（旧名：最新を取得）：論文詳細の上部。`refresh` アイコンと、実行中は「取得中…」（引用数を更新の「更新中…」と同じ作り）。arXivの図解を取り直し、この論文の引用数をOpenAlexから取り直して新しい版として保存する。

## 検証

- 単体：`cites` と `key_sections` の参照検証、`overviewOf`、arXivのanchorと節の取り出し、節の選び方。
- 画面：論文詳細の区分の順、概要・解説の出典、図解の出典リンク、戻るボタン、最新を取得のボタンをヘッドレスChromeで確認する。
- 未確認：実Codexでの `cites`・`key_sections` の出力。

## 追記：論文の更新（2026-10-12）

ユーザー指示：「引用数を更新」は「まとめて最新を取得」にし、空いているフィールドのうち機械的に取れるものを埋める。名前はもっと良いものを。

- 名前：論文タブは「すべての論文を更新」、論文詳細は「この論文を更新」。実行中はどちらも「更新中…」。
- 処理（`POST /api/papers/refresh`、`scripts/paper-refresh.ts`）：論文ごとに、まだ空の書誌（著者・年・会議と種類・DOI・arXiv ID・URL）、アブストラクトとその取得元、コード公開（公開ありはURLと確認日つき）を、arXiv・OpenAlex・Hugging Faceから埋める（Codexの実行の補完と同じ処理）。保存済みの値は上書きしない。引用数は現時点の値としてOpenAlexから取り直し、取得元と取得日を付ける。結果は1つの新しい版として保存し、元に戻せる。
- 「この論文を更新」は、これに加えてarXivの図解と節を取り直す。
- 要点・和訳・概要などCodexの解釈は変えない。
