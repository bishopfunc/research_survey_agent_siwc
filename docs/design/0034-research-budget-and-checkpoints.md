# 0034: 調査期限・書き出し時間・途中保存

状態: Implemented（ローカルPoC、モック試験と実CLIの小さい出力試験）
日付: 2026-10-12 JST
関連: [0029](0029-four-wave-survey.md)、[0012](0012-codex-research-modes.md)

## 目的と実行契約

時間切れで成果を失うことと「終了コード0」の誤解を防ぐ。全体像の強制終了期限を330秒から480秒へ延長し、最初の300秒を調査、残り180秒を書き出しに割り当てる。他の実行も上限の中に書き出し時間を予約する。各Codexの開始時に秒数と絶対時刻の両方を伝える。調査期限はAgentに協調的な終了を指示する期限であり、サーバーがWeb検索を強制的に無効化するものではない。期限到達を経過に記録し、強制終了期限まで書き出しを待つ。

新規調査の各段階は、参照が完結する小さいPatchを `SURVEY_CHECKPOINT` に続くJSONとしてcommentaryメッセージに出す。目安は論文1本または5〜10操作。サーバーは完了したagent_messageイベントのみを読み、型・参照検証を通った累積Patchを実行ごとの番号付きファイルへ即時保存する。未完のJSON、不正Patchは使わない。不正checkpointを受信した段階は、欠落を黙って成功扱いしないため最終応答を使わない（下の時間切れと同じく、検証済みcheckpointまでを理由つきで使う）。最終応答は残りの操作を返し、保存済み操作と統合したPatchを従来の段階検証に渡す。最終応答が全操作を再掲した場合も同じ対象は最終の操作に置き換える。同じ段階で追加した項目への置換は追加の内容の更新、削除は追加の取り消しとして合わせ、取り消した項目につながる追加の関係も外す（2026-10-13、実Codexで最終応答がcheckpointの追加を置換・削除し、存在しないIDとして段階が失敗したため）。途中保存はCommitではない。

時間切れ・取消・起動失敗・完了イベントなしを区別する。時間切れフラグはコード0や遅れて届いた完了イベントより優先する。強制終了期限ではSIGTERMを送り、5秒後も終了しなければSIGKILLを送る。取消・サーバー終了にも同じ停止処理を使う。時間切れ、または最終応答を検証できない段階は、検証済みcheckpointがあればその累積Patchを段階の結果として次の段階へ進み、変更案の説明に「途中保存までの結果を使いました」と理由を残す。checkpointがなければ従来どおり失敗にする。取消後は使わない（2026-10-13、実Codexで全体像が4つのcheckpointを保存したまま8分で時間切れになり、新規調査全体が失敗したため）。checkpointからの自動再開・部分結果の自動Commitは含めない。

## 制約・検証

commentaryのcheckpoint出力と調査期限の遵守はモデルに依存する。checkpointを出さない場合は従来の最終出力だけを使う。実Codexでの出力頻度と所要時間は別途実測し、モック成功と区別する。10分以内の全体完了は保証しない。補完の開始期限480秒は従来どおり。

テスト: 2つの期限、完了時のタイマー解除、SIGTERM→SIGKILL、時間切れ後のコード0・完了イベント、完了イベントなし、checkpointの参照切れ・無効JSON・重複対象の統合・取消後の保存抑止。必須チェックはNode24でnpm ci、npm run check、npm run check:deploy。

最終の残りの操作が空の場合だけ、転送用の型検証は空配列を許可する。累積したアプリのPatchは従来のスキーマ（operationsは1件以上）と参照検証を通す。保存済みDSLの形式は変更しない。
