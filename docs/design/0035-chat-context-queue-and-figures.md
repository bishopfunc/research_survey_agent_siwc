## UIと実行

右端にチャット・詳細のアイコン列を常設する。押したパネルを独立して開閉でき、新しく開いたパネルは既存パネルの左へ追加する。両方を同時に表示でき、それぞれ×で閉じる。詳細にチャット入力欄を重複表示しない。タブレットは中央の下に配置する。スマホは[0033](0033-mobile-research-ui.md)の下部ナビで一画面ずつ切り替える。既存トークンと情報構造を使う。

Shift+クリックした論文は、通常の詳細選択をせず、そのコレクションのチャットのコンテキストへ重複なく追加する。入力欄に題を短く表示し×で外せる。コンテキストはPaper IDの配列（最大20）としてrunに保持し、サーバーはsnapshot中のPaperであることを検証する。PromptではJSONのデータとして渡し、選ばれた論文を依頼の対象とする。論文内容を指示として扱わない。元のユーザー依頼を改変せず、run・説明履歴・Commitの追跡を保つ。送信済みのメッセージにも選択した論文を表示する（Commitはrun_idから、説明履歴は保存したIDから復元する）。

現在の候補3件に加え、「詳しく解説して」「違う視点で調査して」「足りない観点を教えて」を常設する。実行中も入力とコンテキストの追加・削除、待機依頼の追加・削除をできる。入力中の文は実行中の依頼と独立する。

キューはコレクションごとにブラウザ保存する。依頼・コンテキスト・論文キャッシュの指定を送信時に写す。実行中、送信中、変更案の確認待ち、論文の更新中、ほかのコレクションの実行中は待機する。前の変更案を保存または破棄した後、現在表示しているコレクションの先頭の依頼を最新headに対して送信する。過去版から送信しない。失敗時はキューを消さず、明示的な再送を待つ。失敗したrunの再実行は、同じ依頼・コンテキスト・論文キャッシュの指定を新しい依頼IDでキューの先頭に入れ、入力中の文と選択中の論文は変えない。runの状態の取得が404以外（通信断、スリープからの復帰、ゲートの401・502など）で失敗したときは、runを忘れず間隔を延ばして（最大30秒）取り直し、キューも待たせる。待機依頼のIDをrequest_idとして送り、同じ内容の再送は既存runを返す。baseやコンテキストが変わった同じIDは拒否し、待機依頼を削除して送り直すよう理由をそのまま返す。依頼IDとコンテキストの検証エラーも理由を返し、想定外のエラーだけを汎用の文言にする。ブラウザが閉じている間に待機依頼を自動起動する機能はこのローカルPoCでは未実装。進行中のCodexは従来どおりサーバーで続く。自動Commitはしない。

## 図解が欠ける原因と修正

- arXiv IDが空でDOIやURLにのみ識別子がある → DOI・版付きPDF URLのfragmentからもIDを読む。
- キャッシュのある代表図だけをカードで表示し、Agentが指定した最初の図が無い場合に空になる → 保存済みの最初の利用可能な図も候補にする。曖昧な番号を別の図として断定しない。
- arXiv HTMLに節だけあると、図があるかもしれないar5ivへ進まない → 図・表・アルゴリズム・数式が無ければfallbackへ進み、節は保つ。
- 節だけある空の図解キャッシュが古くならない → 図解が空なら1日で再取得。解析器の版を7に上げる。形式の同じ版6のキャッシュは図解があるものだけ再利用し、正常な図を一斉に取り直して表示を遅らせない。
- 指定した図の照合が失敗すると、取得済みのほかの図が折りたたまれたまま → 一つも照合できなければ取得済みの図解を開いて表示する。
- Agentがkey_figuresを出さなかった論文は温める対象にならない → arXiv IDのある全Paperを対象にし、同じIDの取得を共有する。
- 取得失敗は短い状態ラベルと再取得操作を出す。原文の図を使い、架空の図を生成しない。arXiv以外のPDFだけの論文は自動抽出の対象外で、既存のPDF切り出しで代表図を保存できる。

## 論文間の関係

現在のDSLにPaper→Paperの引用関係は無い。関連は課題・手法・系統・主張・出典を使い、引用数は件数のみ。引用グラフの追加はユーザーの質問への回答とは別のDSL/API設計になるため、本変更では引用関係を捏造しない。
