# 0023: 調査のスキルと依頼の振り分け

状態: Implemented（ローカルPoC）
日付: 2026-10-12 JST
対象タスク: P25
関連: [ADR 0014](../adr/0014-skills-as-modules-with-router.md)、[Codexの新規調査と追加調査](0012-codex-research-modes.md)、[論文DBと段階・並行の調査](0021-paper-db-and-staged-runs.md)

## 目的と範囲

ユーザー指示（2026-10-12）：

- 複数ステップのPromptをスキルとして管理し、入力に応じて動的に判定する。
- 新規調査は基本すべてチュートリアルからナレッジまで調べる。入力の例を変える。
- ボタンは「調査」でなく送信の矢印。入力欄は「サーベイしたい研究分野」。
- 追加の入力では、深掘り調査・違う視点の調査・詳しい解説（更新せず解説に徹する）を検出し、スキルで分岐する。

## スキル

スキルは `packages/agent/src/skills/` に1スキル1ファイルで置く。各スキルは、ID・日本語名・版（本文を変えたJSTの時刻）・使う場面（判定に渡す英語の説明と、Lab用の日本語）・出力の種類・手順（日本語の説明とCodexへの指示）・実行の上限時間を持つ。共通ルール（`survey-rules`）はすべての変更案のスキルに付く。

| ID | 名前 | 使う場面 | 出力 |
| --- | --- | --- | --- |
| `survey-new` | 網羅的な新規調査 | 空の調査（判定しない） | 変更案。3段階・並行（[0021](0021-paper-db-and-staged-runs.md)） |
| `deepen` | 深掘り調査 | 特定の課題・手法・論文・小分野をもっと深く・新しく・定量的に | 変更案 |
| `perspective` | 違う視点の調査 | 今の調査が扱っていない観点・隣の分野・反対の結果から調べ直す | 変更案 |
| `explain` | 解説 | 内容の説明・比較・理由を聞く。調査は変えない | 解説（本文・出典・次の候補） |
| `revise` | 修正・補完 | 上のどれでもない追加・修正（名前の変更、分類、和訳、英語表現、ナレッジ、チュートリアルの更新など） | 変更案 |

- 新規調査は、依頼が分野の一側面を挙げていても、その分野全体をチュートリアル・課題・手法・論文・ナレッジまで網羅的に調べる（依頼は分野の指定として扱う）。
- 深掘り・違う視点・修正は従来の追加調査の流れ（1回の実行、検証に落ちたら1回だけ修正）で、指示だけがスキルごとに違う。
- 解説は変更案を返さない。Codexの出力の形式（output schema）を解説用にし、本文（日本語、新しい参入者向けに結論→仕組み→例→限界）、出典（題とURL）、次の候補3つを返す。調査にある情報を先に使い、足りない点だけWeb検索で確かめる。確かめられない点は本文に未確認と書く。

## 判定

- 調査が空なら判定せず `survey-new`。
- 中身があれば、最初に短い判定を1回走らせる（Codex、Web検索なし、上限90秒）。渡すのは、依頼の文と調査の要約（題、課題・手法・系統の名前、論文の数）、スキルの一覧（IDと使う場面）。返すのは `{ skill, reason }`（output schemaで固定）。
- 判定が失敗・時間切れ・形式違反なら、語句による判定（`guessSkill`）に切り替える：解説の語（解説・説明・教えて・とは・なぜ・違い・わかりやすく）があり調べる語（調べ・追加・加えて・深掘り・調査・更新）が無ければ `explain`、深掘りの語なら `deepen`、視点の語（視点・観点・別の・違う・異なる・他分野・隣接）なら `perspective`、それ以外は `revise`。
- 判定の結果と理由は実行の経過に1行出し、選んだスキルの名前を実行の見出しに出す。実行の記録（`prompt_version`）には判定とスキルの版を残す。

## 画面

- 送信ボタンは矢印のアイコン（実行中は回転する印）。新規調査とチャットの入力欄は、調査が空なら「サーベイしたい研究分野」、中身があれば「追加の依頼」。
- 新規調査の例は「〜を網羅的にサーベイ」。
- 解説の結果はチャットにCodexの発言として出し（本文と出典のリンク）、変更案・保存は出さない。閉じたあともチャットに残す（このブラウザに保存、コレクションごと）。

## 契約

- `Run` に `skill`（ID）と `explanation`（`{ message, sources }`）を足す。解説の実行は `patch` を持たない。
- 解説の出力：`message`（1〜12000字）、`sources`（最大20、`{ title, url }`、URLはhttp/https。URLが空・DOI文字列などhttp/https以外の出典はその出典だけ除き、解説は使う）、`follow_ups`（最大3）。
- 判定の出力：`skill`（`deepen`・`perspective`・`explain`・`revise`）、`reason`（最大200字）。
- DSL（調査の型）は変えない。

## 失敗と競合

- 判定に失敗しても実行は止めず、語句による判定で続ける（経過に出す）。
- 取消は判定中・スキルの実行中のどちらでも効く。
- 解説の出力が形式に合わなければ、実行は失敗として本文を出さない。

## 検証

- スキルの一覧（IDの重複なし、版の形式、指示が空でない）、新規調査の指示に網羅の規則があること。
- 語句による判定（解説・深掘り・視点・修正の例）、判定の出力の検査（未知のスキル・空の理由を拒否）、判定のPromptに調査の全体（論文本文など）を入れないこと。
- 解説の出力の検査（URLの形式、長さ）。
- 画面：送信ボタン、入力欄の表示、解説の表示はヘッドレスChromeで確認する。実Codexでの判定と解説は状態・実測に記録する。

## 画面の追記（2026-10-12、ユーザー指示）

- 新規調査の例は研究分野の名前だけ（VLN、拡散言語モデルの強化学習、LLMの推論、MAPF、ロボットの歩行制御、ヒューマノイド、3DGSにおける自己位置推定、3D-CAD Agent）を3段の横スクロールで出す。依頼の言い回しにかかわらず新規調査は網羅的に調べる（「〜について網羅的にサーベイして」を付ける案はユーザー指示で取りやめた）。
- 中央の入力欄と右タブのチャットの入力欄は同じ内容を表示する。サーベイ中は依頼を表示したまま入力できず、取消すと入力できる。
- 新規作成では右のパネルを閉じたまま始め（チャットの状態は同期する）、実行の経過と変更案は中央の入力欄の下に出す。利用者がパネルを開くか、調査に中身ができれば通常の表示に戻る。パネルの開閉の保存した設定は変えない。
- コレクション名は調査のタイトル（最新の版の title）と同じものを表示する。見出しとコレクションのペンのアイコン（コレクションはダブルクリックも）で変えると、タイトルを変えた新しい版を作り、コレクション名も同じにする。
