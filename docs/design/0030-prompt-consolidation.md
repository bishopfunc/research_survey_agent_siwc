# 0030: Promptの統合とスリム化

状態: Implemented（ローカルPoC、モック試験のみ）
日付: 2026-10-12 JST
対象タスク: P32
関連: [0012 Codexの調査](0012-codex-research-modes.md)、[0023 スキル](0023-skills-and-routing.md)、[0025 事実と出典](0025-facts-and-sources.md)、[0028](0028-eight-step-survey.md)・[0029](0029-four-wave-survey.md) 新規調査の手順

## 目的

ユーザー指示（2026-10-12）：スキル（Prompt）が肥大化しすぎている。矛盾する部分を整理して統合し、スリムにする。ただし、これまでのフィードバックで指示したことは守る。

## 方法

1. 共通ルール・調査の手順・スキルとルーター・これまでの指示（status・設計・ADR・テスト）を4方向から洗い出した。要件は、共通ルール169件・手順91件・スキル85件・ユーザー指示103件。矛盾は63件。
2. 洗い出しから統合計画を作り、別の検証者が抜けと誤りを指摘した（指摘28件を反映）。
3. 書き直した後、ユーザー指示のうちPromptに関わる96件の残り方を、要件ごとに検証者が確かめた（次節）。

## 構造の決定

- **共通ルールは書き方、手順・スキルの指示は何を書くか**：共通ルール（`PROMPT_RULES`）は、課題・手法・論文・ナレッジ・出典・チュートリアルなどの書き方を1か所ずつ決める。手順やスキルの指示は「この実行で何を書くか」だけを書き、書き方はルールをidで参照する。`role` に優先順位を1文入れた：何を書くかはモードの指示が決め、制限はモードの指示を優先する。
- **ルールはidで参照する**：各ルールを `[id] 本文` の1行にして改行で連結し、指示は `[facts]` `[issues]` のように参照する。これまでの「the cache rule」のような名前はCodexに見えなかった。idの変更：`evidence`→`facts`、`library`→`cache`（指示の呼び名に合わせた）。参照先が存在することを試験で確かめる。
- **ルールは32個から21個**：`provenance`・`deletion`・`draft`・`claim`・`links`・`venue`・`abstract`・`code`・`figure`・`blogs`・`claims` を、`role`・`locality`・`validator`・`bibliography`・`keepstored`・`guide`・`paperparts`・`issues` などに統合した。
- **サーバーやスキーマが保証することは短く**：未検証のEvidence（`unverified` 固定）、ナレッジの分類、URLの形式、候補の上限、`reading.evidence` の導出、書誌・アブストラクト・コードの補完は、Promptでは数語にするか書かない。
- **使われていない指示を削除**：一括の新規調査（`NEW_SURVEY_INSTRUCTIONS`）、旧来の追加調査（`ADDITIONAL_RESEARCH_INSTRUCTIONS`）、`RESEARCH_MODES`。新規調査は段階実行、追加の依頼はスキルで動くため、実行時に使われていなかった。`buildSurveyPrompt` は指示を必須にした。
- **基準のチュートリアルは書く指示にだけ付ける**：サンプルの章立て（約1,600字）を共通ルールから外し、チュートリアル全体を書く手順（チュートリアルのAgent）と、reviseのチュートリアルの手順にだけ付ける。
- **修正と解説の抜粋**：修正（repair）に付けるルールは `untrusted`・`locality`・`keepstored`・`validator` の4つ。返答形式と由来は修正の指示に書く。解説に付けるルールは `purpose`・`critical`・`tools`・`untrusted`・`cache`・`nofabrication`・`paperparts`。

## 主な矛盾の解消

- 出典の確認状態：Codexが書けるのは `unverified` だけ（スキーマで固定）。`abstract_only` の指示を消した。
- 出典元：論文と一次の文献（サーベイ、データセット・ベンチマーク・リーダーボード・シミュレータ・モデルの公式ページ）。入門記事・講義ノート・ブログ・記事・スライド・講演は手がかりで、出典元にしない。
- キャッシュ：要点（reading）のある論文は読み直さない。要点が空の論文は未読で、手順やスキルの指示が割り当てたときだけ読む。
- ライブラリの論文：保存済みの要点を写す。写した要点は出典（cites）を持たず、事実と出典の規則の唯一の例外。数値の無い達成度の主張だけは出典なしでよい。
- 論文と手法・課題のつながり：`Paper.proposes`・`Paper.addresses` だけで書き、Relationにしない（関係の一覧からもPaper起点を外した）。
- 系統と手法の名前：系統は共通の考え方の日本語名で代表手法の名前にしない。手法はアプローチ群の総称で、発端の手法があれば「（〜系）」を添える。
- 課題：説明は一文（概要の規則）。論文ごとの候補から3階層以上の木にする。採点の課題数の上限を12から30にした（3階層以上の木と両立させるため）。
- 段階ごとの書き分け：統合（手順3と6）は追加調査の候補3つを書き、チュートリアルは書かない。チュートリアルは別のAgent。補完（手順8）は候補を書き直す。
