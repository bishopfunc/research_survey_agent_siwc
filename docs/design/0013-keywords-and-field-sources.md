# 0013: キーワード（用語集）と分野の既存ソース

状態: Implemented
日付: 2026-10-12 JST
対象タスク: P12
関連: [Codexの調査](0012-codex-research-modes.md)、[調査Prompt](0007-survey-discovery-prompt.md)、[DSL調整ガイド](../dsl-schema.md)、[ADR 0007の互換方針](../adr/0007-paper-code-compatibility.md)

## 目的と範囲

ユーザー指示（2026-10-12）による2点。

1. 新しい小分野は、分野の既存ソース（サーベイ論文、awesomeレポジトリ、ブログ・記事）から調べる。
2. 論文からキーワードと意味を取り出し、分野の初心者が用語から追いつけるキーワードタブを置く。

## 分野の既存ソース

新規調査の第2段階を「2a サーベイ論文、2b awesomeレポジトリ、2c ブログ・記事」の並行に広げる。追加調査で新しい小分野を扱うときも、同じ3種類を並行して調べてから一次論文へ進む。

ブログ・記事は、研究室・学会・企業の技術ブログ、チュートリアル、解説記事を対象とする。用語や流れをつかむ手がかりとして使い、URL・著者または組織・公開日を残す。主張の根拠には使わず、一次論文で確かめる。

## キーワード（DSL）

Entityに `Keyword` を追加する。既存の型やsnapshotは変えず、追加だけなのでschema_versionは0.1.0のまま。過去のデータはキーワードが無いだけで、そのまま有効。

| 項目 | 内容 |
| --- | --- |
| `label` | 用語（例 Sum-of-costs） |
| `aliases` | 別名・略称（例 SOC） |
| `category` | `task` / `dataset` / `benchmark` / `metric` / `baseline` / `concept` / `method` / `other`（2026-10-12に `baseline` を追加） |
| `meaning` | 初心者向けの日本語の説明。生成した説明であり、確認済みの事実として扱わない |
| `papers` | その用語を定義・中心的に使う論文のID |
| `related` | 関連する課題・手法・共通概念・分野のID（ベースラインならそのMethod） |
| `official_url` | 任意。データセット・ベンチマークの公式ページ、リーダーボード、コード。確認できたものだけ |
| `definition_excerpt` | 論文などの定義文の原文（任意。空でよい） |
| `source_url` / `locator` | 原文がある場合の取得元URLと位置。原文があればURLが必要（0011の原文とリンクの規則） |

検証：`papers` はPaper、`related` はIssue/Method/Concept/Domainを参照する。参照切れ・型違い・重複は拒否する。原文がありURLが無い場合と、http(s)以外のURLは拒否する。

追記（ユーザー指示）：代表的なタスク・データセット・ベンチマーク・ベースラインもキーワードとして集める。新規調査はサーベイと一次論文から標準のタスク・データセット・ベンチマーク（主な評価指標）・ベースラインを記録し、キーワードに含める。サンプルにMoving AI LabのMAPFベンチマーク（公式ページの一文を定義の原文として保存）と、比較の基準としてのCBSを加えた。

## 画面

タブ「キーワード」を論文の後に置く。分類で絞り込み、検索は用語・別名・意味に効く。カードは用語・別名・分類・意味・登場する論文を示し、選ぶと右に詳細（定義の原文と出典、関連する課題・手法・論文、つながり図）を出す。「＋キーワード」で手入力、「論文から抽出」でCodexの追加調査に「調査にある論文からキーワードと意味を抽出」という依頼を送る。説明文は画面に置かない。

## Prompt

新規調査の出力に、読んだ論文から分野の主要なキーワード（10〜20件程度）を加える指示を入れる。用語・別名・分類・初心者向けの意味・登場する論文・関連する課題と手法を入れ、取得したページに定義文があれば原文と出典URL・位置も入れる。追加調査では、依頼で新しく出た用語を加える。調査にある論文から抽出するときは、保存済みのアブストラクトや概要を使い、頼まれない限り論文を読み直さない。

## 検証と完了条件

既存snapshotの互換、Keywordの参照・原文とURLの検証、つながり図への反映、Promptの指示、strict準拠の出力スキーマ、タブの表示と絞り込み・検索、詳細と編集フォーム、Labの型表示を確認する。実Codexでキーワードの抽出を1回実行し、検証を通ることを確かめる。
