# 0015: 引用数の取得

状態: Implemented
日付: 2026-10-12 JST
対象タスク: P14
関連: [DSL調整ガイド](../dsl-schema.md)（citation_count・citation_source・citation_as_of）、[MVP設計](0001-mvp.md)

## 目的と範囲

ユーザー指示（2026-10-12）「引用を取得できるようにして google scholar APIなど」による。調査にある論文の引用数を外部の論文データベースから取得し、取得元と取得日と一緒に保存する。

## 取得元の選定

| 候補 | 判断 |
| --- | --- |
| Google Scholar | 公式APIが無い。画面の自動取得は利用規約で禁じられている。SerpApiなどの代行は有料・要APIキーで、規約上の扱いも不明確。採用しない |
| OpenAlex | 無料、キーなしで使える（無料キーで上限10倍）、`cited_by_count` を返す。DOIは1回の絞り込みで最大100件をまとめて問い合わせられる。毎秒100件を超えると429。第一候補 |
| Semantic Scholar | 無料、`citationCount`、一括取得あり。キーなしは全利用者で共有の上限で、混雑時に絞られる。OpenAlexで見つからない論文（arXivのみ等）の補完候補 |

引用数は取得元ごとに違う（Google Scholarは一般に多く数える）。値には必ず取得元（`citation_source`）と取得日（`citation_as_of`）を付け、取得元をまたいで比べない。

## 現状と変更

- 論文タブの上に「引用数を更新」。押すとローカルサーバーが調査の全論文（最大200件）をOpenAlexで照会し、見つかった論文の引用数・取得元（`OpenAlex`）・取得日（JSTの日付）で新しい版を作る。通知の「元に戻す」で戻せる。見つからない論文は値を変えず、件数を通知に出す。
- 照合の順（`scripts/citations.ts`）：
  1. 出版社のDOI（正規化して完全一致、40件ずつまとめて照会）。
  2. タイトルの完全一致（記号・大小・空白を除いて比べる。3語以上のタイトルだけ、最大30件、出版年±1）。同じタイトルの版が複数あれば年の近いもの、次に引用の多いもの。
  3. arXivのDOI（`10.48550/arXiv.<id>`）。プレプリントだけの記録で、出版版と別に数えられ少なく出るので最後にする。
  曖昧な一致（タイトルが違う）は採らない。例：サンプルのICBSは論文名に「The」が無く一致しないため「未発見」になる。
- サーバーは固定のホスト（api.openalex.org）だけに問い合わせ、メールアドレスなどは送らない。任意の環境変数 `OPENALEX_API_KEY` があればキーを付ける（ログ・Gitには出さない）。1回の問い合わせは20秒で打ち切る。
- 論文の詳細の引用数は「1261（OpenAlex・2026-10-12）」のように取得元と取得日を付ける。
- 2026-10-12追記（ユーザー指示「なぜ引用数はデフォルトで埋まらないのか」）：Codexは取得したページに書かれた引用数しか入れない規則のため、調査の結果では未取得になる。Codexの変更案を保存した直後に、引用数の無い論文だけを自動でOpenAlexに問い合わせ、もう1つの版（「引用数を更新（OpenAlex・N件）」）として保存する。通知の「元に戻す」で引用数の版だけを戻せる。

## 契約とデータ

DSLは変えない（citation_count・citation_source・citation_as_ofは既存）。PoCでは現在値をsnapshotに入れ、更新は新しい版にする（既存の方針。MVPで最新値の別保存を検討）。

## 失敗と競合

429・通信失敗・時間切れは通知に短く出し、それまでに取れた分は反映する。過去の版を表示中は押せない。応答を待つ間に調査が変わった（編集・保存・コレクション切替）ときは保存しない。

## 検証と完了条件

単体試験（`test/citations.test.ts`）：DOI・arXiv ID・タイトルの正規化、出版DOIの一括照会、arXivだけの論文がタイトルで出版版を見つけること、プレプリントDOIが最後であること、違うタイトル・短いタイトルを採らないこと、エラー時に取れた分を残すこと、入力の検証。実際のOpenAlexでの確認は状態・実測に記録する。

## 未解決事項

## 根拠

- OpenAlex：キーなしで利用でき無料キーで上限10倍、毎秒100件超で429、1つの絞り込みに最大100件のOR、`cited_by_count` による絞り込みと値（help.openalex.org の Rate limits and authentication・Filter works、2026-10-12確認）。
- Semantic Scholar：キーなしの利用は全利用者で共有の上限、キーありは初期1 RPS（semanticscholar.org/product/api、2026-10-12確認）。
