# 0033: スマホの調査・詳細・チャット切り替え

状態: Implemented（ローカルPoC・ブラウザのタッチ操作エミュレーション）
日付: 2026-10-13 JST
関連: [0032](0032-chat-context-queue-and-figures.md)

## 選択と範囲

幅768px以下では「調査・詳細・チャット・コレクション」の下部ナビゲーションで、一画面ずつ切り替える。論文を選ぶと詳細を開き、閉じると調査に戻る。詳細の「チャットに追加」は論文をコンテキストに追加してチャットを開く。キーボードを使わない操作でもShift＋クリックと同じ結果になる。既存の配色・トークン・調査ビューを使う。769px以上の独立パネルは維持する。

縦積みでは長い調査の末尾まで移動しなければチャットに届かない。ボトムシートでは論文・図表を読む高さが不足し、スクロールが重なる。そのため全画面切り替えを採る。小さい画面の下部ナビゲーションは[Androidのadaptive navigation](https://developer.android.com/develop/adaptive-apps/guides/build-adaptive-navigation)も参考にした。UIだけの可逆な変更であり、保存形式・API・Prompt・DSLを変更しない。

## 表示と入力

調査のスクロール位置、詳細選択、チャット下書きは画面を切り替えても維持する。コレクションには新規・サンプル・フォーク操作を置き、選択後は調査へ戻る。操作領域は44px以上を基本にする。画面のタブは横方向に内部スクロールし、図表やツリーの内部スクロールを維持する。本文の折り返しでページ全体の横あふれを防ぐ。

チャットは会話部分だけをスクロールさせ、入力を下端に置く。safe-areaを考慮し、[VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)の高さとoffsetで表示領域を合わせる。入力フォーカス中に表示領域が縮んだ場合は下部ナビを隠す。ピンチズームはキーボード縮小として扱わない。textareaは16px以上とし、iOSの入力時ズームを避ける。閉じる操作とEscapeで調査へ戻る。

## 受け入れと検証

320/375/414/768pxでページ全体が横にはみ出さず、下部ナビから直接各画面へ移動できる。論文のタップ→詳細→コンテキスト追加→チャット、下書きを維持した往復、コレクション選択、閉じる操作をブラウザで確認する。1024/1440pxでデスクトップ表示を確認する。表示領域縮小はブラウザ内で模擬するが、実機のOSキーボード・Safariは別の未確認事項として記録する。必須checkとcheck:deployを実施する。公開・LAN公開・認証境界の変更は含まない。
