# 0004: UI・Agent Prompt・DSLの開発レビューLab

状態: Implemented
日付: 2026-10-12 JST
対象タスク: P03

## 目的

ユーザーがアプリのコアロジックをまとめてレビューできる開発者向け画面を `/lab` に作る。UI、Agent Prompt、DSLを画像・アーキテクチャ図・日本語の説明・動く実例で示す。通常の製品画面ではDSL/JSONを表示しない方針を維持する。

## 内容と実装

- 概要：UI→Codex→Patch検証→差分確認→Commitの図と、PoCの実装済み・未実装の区別。
- UI：実際のアプリをレビュー用の隔離プレビューで操作する。サンプルから開始し、編集とForkはプレビュー内のメモリに保存する。本人の保存済み調査やCodex実行へ影響させない。
- Agent Prompt：実行時と同じ共有モジュールから指示文を表示する。日本語の要点と実際の英語指示、入力・出力・実行条件、未実装の調査機能を明示する。
- DSL：実際のJSON Schemaから情報・関係・評価条件・Patchの型、必須フィールド、enum、変更操作を表にする。型同士の関係図、IssueのkindとClaimのstatusの区別、引用数のnull、コード公開状況と確認日、版の不変性を説明する。
- 検証例：同じdomain validatorで正常・参照切れ・循環・不正な引用数を試し、適用可否を見る。生JSONの貼り付けは不要。
- レビューメモ：3対象ごとに未確認・要修正・確認済みとコメントをこのブラウザへ保存し、Markdownで出力できる。レビュー状態は検証結果や承認の証明とは区別する。

`packages/agent/src/prompt.ts`をPromptの正本とし、ローカルCodex起動とLabの両方が参照する。Labは新規Reactコンポーネントとして追加する。既存の製品ルートとコンポーネントを削除・作り直さない。Promptの分離では指示の意味を変えない。

## 表示方針

Hallmarkを適用し、既存の白・濃いグレー・オレンジを保持する。研究レビュー用の目次と、内容の異なる3領域で構成する。見せかけのブラウザ枠・架空の指標・装飾的な画像は使わない。図は実装の境界に合わせる。デザイントークンを `tokens.css` にまとめ、Lab専用CSSから参照する。

## 境界と検証

ローカルPoC用の開発画面。Cloudflare Worker公開URLの `/lab` は未対応。認証情報・過去runの生ログ・個人の保存済み調査を表示しない。UIプレビューのAgent操作は無効化する。

型検査、既存テスト、build、Worker dry-runを行う。ブラウザで `/lab` の直アクセス、UIプレビュー、Prompt一致、検証例、レビューの再読込と出力、320/375/414/768px幅を確認する。
