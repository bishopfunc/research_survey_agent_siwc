# 0004: Agent PromptとDSLの仕組みを説明するLab

状態: Implemented
日付: 2026-10-12 JST
対象タスク: P03（2026-10-12 JSTに目的を変更）

## 目的

`/lab` は、調査が作られる仕組みを開発者が理解するための画面である。
扱うロジックは2つある。
Codexに渡す指示（Agent Prompt）と、調査を保存する形式と検証の規則（DSL）である。
通常の製品画面ではDSLやJSONを表示しない方針を維持し、その説明はこの画面と文書に置く。

当初はUI、Agent Prompt、DSLの3つをレビューする画面として作り、UIの隔離プレビューとレビューメモ（状態、コメント、Markdown出力）を置いていた。
2026-10-12 JSTのユーザー指示（「labからUIを削除」「開発レビュー機能は不要、ロジックを理解させるように」）で、UIの節とレビュー機能を外した。
UIの説明は、各機能の設計文書に置く。

## 構成

ページは、依頼から保存までの流れを先に示し、続けて2つのロジックを説明する。
目次は左に固定し、各節へ移動できる。

- **全体の流れ**：依頼、Codex、検証、確認、Commitの5段階の図。段階を選ぶと、その段階の処理と実行場所を表示する。実装済みと未実装の範囲も並べる。
- **Codexへの指示**：
  - スキルの選び方：調査が空なら新規調査、中身があればWeb検索なしの判定でスキルを選ぶ流れ。判定の指示の実例。
  - 実行の時間軸：新規調査と追加の依頼で、どのCodexの実行がいつ・何本並行し、何分使い、何を書き出すかの図（2026-10-14、ユーザー指示「どれが並列でどれが何分何を書き出しているか不明」）。行は実行（作業の本数つき）、棒は上限時間で、調べる時間と書き出しに予約した時間を塗り分ける。各段階が上限まで使った場合の配置で、段階のあいだのサーバーの書誌補完と、早く失敗した作業のやり直しの時間は含めない。同時に動くCodexの数も同じ時間軸に示す。行を選ぶと、受け取るもの、書き出すもの、途中保存の有無、実際の英語の指示を表示する。図は `STAGE_TIMEOUT_SECONDS`、並行数、`timeBudget`、各段階の指示の関数から作るので、値や指示を変えると追従する。波の順序（全体像→精読と発散→統合とチュートリアル→検査と補完）は `scripts/staged-run.ts` と同じ形を手で写しているため、段階実行の順序を変えたときは更新する。
  - 新規調査の手順：`RESEARCH_STEPS` の各手順（水準、実行の区分、説明、英語の指示）と、手順のあいだでサーバーが行う処理（精読の割り当て、作業の変更範囲の制限、課題の候補の後処理、失敗の扱い）。
  - 追加の依頼のスキル：各スキルの用途、手順、出力の種類、上限時間、英語の指示。
  - 共通のルール：題を一覧にし、開くと説明を表示する。実際の英語の指示も読める。
  - 実行の条件：モデル、道具、Sandbox、同時実行、書誌の補完、論文キャッシュ、検証に通らないときの修正、保存。修正の指示も読める。
- **調査の保存形式**：
  - 項目と関係：分野から根拠までのつながりの図、そのほかの項目（系統、ナレッジ、文献、チュートリアル）、保存の規則。
  - 型の定義：JSON Schemaから、型ごとの項目、意味、値の形式、必須かどうかを表にする。
  - 変更案の検証：検証の対象と、サンプルに違反を1つ入れて実際の検証関数に通す例（正常、参照切れ、派生の循環、負の引用数）。
  - 調査の要件：サンプルの調査とチュートリアルを、実行結果の採点と同じ採点表にかけた結果。

指示文、型の定義、検証、採点は、実行時と同じモジュールから読み込む。
`packages/agent/src/prompt.ts`、`research-prompt.ts`、`skills/` をPromptの正本とし、ローカルのCodex起動とLabの両方が参照する。
新規調査の手順の一覧は `RESEARCH_STEPS` から作るので、手順を変えてもLabの一覧は自動で追従する。
手順のあいだの処理を説明する文は手書きなので、段階実行（`scripts/staged-run.ts`）の振る舞いを変えたときは更新する。

## 表示方針

Hallmarkを適用し、アプリと共通の `tokens.css`（[0009](0009-researchrabbit-ui.md)の配色）を使う。
長い説明は段落に分け、一覧は題だけを先に見せて詳細は開いて読む形にする。
見せかけのブラウザ枠、架空の指標、装飾的な画像は使わない。
図は実装の境界に合わせる。

## 境界と検証

ローカルPoC用の画面である。
Cloudflare Workerの公開URLの `/lab` には対応していない。
認証情報、過去の実行の生ログ、個人の保存済み調査は表示しない。

型検査とbuildを行う。
ブラウザで `/lab` の直接アクセス、各節の表示、検証例の切り替え、320、375、414、768px幅での横溢れと2行になる操作要素の有無を確かめる。

アプリの `?preview=lab`（UIの隔離プレビュー）は、Labから参照しなくなった。
削除するかどうかは未決である。
