# 0025: 事実と出典

状態: Implemented（ローカルPoC）
日付: 2026-10-12 JST
対象タスク: P27
関連: [ADR 0017](../adr/0017-evidence-as-common-source.md)、[文献ガイド](0024-literature-guide.md)、[DSL調整ガイド](../dsl-schema.md)

## 目的と範囲

ユーザー指示（2026-10-12）：すべての論文と文献ガイドから抽出するものの基本は「事実」と「出典」。事実は、ナレッジの各種・課題・手法・主張・論文の要点の各種になる。このようにPromptとDSLを組み直し、MAPFのサンプルも作り直す。あわせて論文詳細を「概要／主張と根拠／事実と出典／メタ情報」の階層にし、アブストラクトは閉じない。

## DSL

- 出典＝Evidence（型名は保存済みの調査のため変えず、画面では「出典」）。出典は「どこから（`origin`：論文か文献ガイドの項目のID）・どこに（`locator`）・何と書いてあるか（`excerpt`、原文の写し）・URL（`source_url`）・確認状態（`verification`）」を持つ。`origin` は任意項目で、保存済みの出典には無い。
- 事実＝調査の項目。課題（Issue）・手法（Method）・系統（Concept）・ナレッジ（Keyword）に任意の `evidence`（出典のID）を足す。論文の要点（Reading）にも `evidence` を足す（従来の `sources` はURLと位置だけで原文を持たないため、新しい出力では使わない。保存済みのものは表示を続ける）。主張（Claim）と論文（Paper）は従来どおり `evidence` を持つ。
- 検証：`origin` はPaperかResource、`evidence` はEvidenceを指す。

## Prompt

共通ルールに facts（事実と出典）を置く：論文と文献ガイドの項目から取り出すものは、事実と出典の組。事実（課題・手法・系統・ナレッジ・主張・論文の要点）を書くときは、この実行で開いたページの原文を写した出典（Evidence）を作り、`origin` に論文か文献ガイドの項目のID、`locator` に位置、`source_url` にURLを入れ、事実の `evidence` から参照する。出典が無いことは事実として書かない（未確認としてmessageに書く）。既存の evidence・claims・knowledge・papers の規則を、この形に合わせる。

## 画面

- 課題・手法・系統・ナレッジ・主張の詳細に「出典」：原文の引用、出典元（論文か文献。押すと詳細）、位置、リンク。
- 論文詳細の階層：
  1. 概要：どんなもの？、アブストラクト（和訳と原文、開いたまま）、要点（貢献・先行研究との差・キモ・検証・議論）、理解に重要なFig・アルゴリズム・数式、代表Fig
  2. 主張と根拠：主張（状態・条件・時点）とその根拠
  3. 事実と出典：この論文を出典元とする事実（課題・手法・系統・ナレッジ）と、その出典の位置
  4. メタ情報：出版・引用数・コード・著者・ID
- 出典（Evidence）の詳細：原文、出典元、位置、確認状態、リンク。

## サンプル

MAPFのサンプルを作り直す：課題7・手法9・系統3・ナレッジ・論文の要点に、アブストラクトの原文（arXiv APIとOpenAlexで取得済み）から写した出典を付ける。ICBSは本文もアブストラクトも取得していないため出典を付けない（事実として書けない点が見える）。Moving AIのベンチマークのページを文献ガイドに足し、ナレッジの出典元にする。

## 検証

- 出典の参照（origin・evidenceの型）、Promptのfacts規則、サンプルの事実がすべて出典を持つこと（ICBSを除く）、サンプルの出典の原文が出典元のアブストラクトに含まれること。
- 画面：論文詳細の4区分とアブストラクトが開いていること、課題・手法の出典をヘッドレスChromeで確認する。

## 追記：出典は本文から（2026-10-12）

ユーザー指示：「事実と出典はアブストラクトだけでなく本文から取得すること」。

- Prompt（[facts]・[papers]）：出典は、この実行で開いたページの本文から、その事実を述べた節・表・アルゴリズム・定理・キャプションを写し、位置（「Section 4.2」「Table 2」など）を付ける。アブストラクト（位置「Abstract」）は、本文のどこにも無いことか本文を取得できないときだけ使い、そのことをmessageに書く。要点の項目ごとの出典（cites）も本文の該当箇所から（キモは手法の節、検証は結果の表、議論は限界や考察の節）。
- 採点と点検：「本文まで読んだ」は、要点の出典に本文の出典（位置がAbstract以外）がある論文だけを数える。サーバーの点検（手順7）は、要点の出典がアブストラクトだけの論文を補完の対象に挙げる。
- サンプル：arXivにある9本はHTML版の本文（Markdownに変換）から、arXivに無いCBS（AAAI 2012）とECBS（SoCS 2014）はAAAIの公開PDFから、要点の各項目と事実の出典を写した（140件、確認状態は原文を確認済み、ページのSHA-256つき）。各抜粋がページの本文の部分文字列であることを機械的に確かめ、別の検証者が各抜粋が項目を支えるかを確かめた（不支持8件を除外）。本文と食い違う要点は本文に合わせて直した。CBSのジャーナル版（AIJ）は本文が公開されていないため、本文の出典が無いまま点検に挙がる。
- 未対応：本文をサーバーでMarkdownにしてCodexに渡す仕組み（いまはCodexが自分で開いて読む）。
