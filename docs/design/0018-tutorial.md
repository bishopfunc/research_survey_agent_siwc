## 目的と範囲

ユーザー指示（2026-10-12）「チュートリアルタブを追加」。理想は https://kei18.github.io/note/posts/mapf-tutorial/ で、そうなるように試験要件を決める。参入者が最初に頭から読める読み物を、調査の内容（論文・手法・課題・ナレッジ）から作り、調査の各項目へ行き来できるようにする。

## 理想の構成（参照した記事の分析）

問題設定（グラフ・記法・衝突・目的関数を数式で）→なぜ面白いか（応用と出典）→解き方（素朴なA*から、CBS・有界準最適・優先度つき計画・LNS2・PIBT・LaCAMへ。各段で前の方法の限界を説明し、図・擬似コード・規模の目安を示す）→まとめと選び方（場面ごとの推奨）→派生問題（短い説明と出典）→手を動かす（コード・可視化）→さらに学ぶ（講演・学会・資料）→おわりに。

## DSL

新しいEntity型 `Tutorial`（1つの調査に1つ）。`label`（題）と `sections`（順に並ぶ節）。節は `role`（definition・motivation・methods・summary・challenges・variants・hands_on・further_reading・conclusion）、`heading`、`body`（日本語。引用は `[@ID]`、数式は `$…$` と単独の行の `$$…$$`、`- ` の行は箇条書き）、`refs`（参照する項目のID）、`media`（引用する論文の図・アルゴリズム・数式。`{paper, label}`、labelは「Figure 2」「Algorithm 1」「Eq. (3)」）、`links`（`{url, title}`、http(s)のみ）。検証：引用・refsのIDが存在し根拠・チュートリアル以外の型、media.paperは論文、リンクはhttp(s)、チュートリアルは1つまで。

## 試験要件（採点表）

`assessTutorial`（`packages/domain/src/tutorial.ts`）で、Codexの出力ごとに構造を確かめる。Labに表示する。

| 要件 | 確かめ方 |
| --- | --- |
| チュートリアルがある | Tutorialが1つ |
| 問題設定 | definitionの節に単独行の数式と出典 |
| 動機と応用 | motivationの出典が2つ以上 |
| 解き方の数 | methodsの節が4つ以上 |
| 素朴な方法から最新へ | 教える順（年の順でなくてよい）。各節が年のある論文を引用し、最後の節の最新の論文が全節の最新から1年以内（2026-10-12に「年の順」から変更：理想の記事も年の順ではない） |
| 前の方法の限界から | 2節目以降の本文に限界を示す語（限界・弱点・しかし・ただし・難し…） |
| 図・アルゴリズム・数式 | methodsの2節以上にmediaか単独行の数式 |
| 図のキャプション | すべてのmediaに日本語のキャプション（`caption_ja`、論文のキャプションの忠実な和訳）がある（2026-10-12追加、ユーザー指示「チュートリアルのcaptionも日本語に」）。表示は caption_ja → 論文の reading.captions_ja → 原文の順 |
| 図（画像） | arXivにある論文の図（labelがFigure・Fig・図）を、definitionかmethodsの2節以上のmediaに入れる（2026-10-12追加、ユーザー指示「チュートリアルに画像が必要」。数式だけで上の要件を満たし画像が1枚も無いチュートリアルを落とす。画像はarXiv HTML版から取るので、arXivに無い論文の図は数えない） |
| まとめと選び方 | summaryの出典が2つ以上 |
| 課題と達成度：節の数 | challengesの節が3つ以上（課題ごとに1節）。2026-10-12追加（ユーザー指示：チャレンジの項目を足し、課題と達成内容を解説する。手本は https://huyenchip.com/2023/08/16/llm-research-open-challenges.html ：課題ごとに、問題・なぜ重要か・進展（数値と出典）・未解決の問いを書き、最後に解決の度合いと難しさを比べる） |
| 課題と達成度：課題 | 各節が調査のIssueを引用する（課題ツリーとつながる） |
| 課題と達成度：到達点 | 各節が、引用したIssueについて（about）のClaimを引用する。達成度の主張に数値・条件・時点を持たせる規則（issuesの規則）と合わせて、記事の「進展を数値と出典で示す」に当たる |
| 課題と達成度：根拠 | 各節が論文を2本以上引用する |
| 課題と達成度：解決の度合い | 各節の本文に、未解決・部分的に解決・解決済みなどの語がある（記事は明示しないが、まとめで難しさを比べている。ここでは節ごとに書かせる） |
| 課題と達成度：未解決の問い | 「- …？」の箇条書きの問いを挙げる節が1つ以上（記事の人の好みの節の、番号つきの問いに当たる） |
| 派生問題 | variantsの出典が3つ以上 |
| 手を動かす | hands_onにリンク |
| さらに学ぶ | further_readingの出典とリンクが合わせて2つ以上 |
| 節の順序 | 役割の順序を守る |
| 分量 | 本文3000字以上 |

構造の検査であり、内容の正しさは保証しない。内容は引用（[@ID]）から原文へたどって確かめる。サンプル（MAPF。衝突を分岐する探索・学習ベース・優先度で決める解法にわたる7節の解き方と、arXivの図6枚）はすべての要件を満たす。

## Prompt

共通ルール tutorial（`survey-rules@2026-10-12T13:04+09:00`）：上の構成と要件、引用と数式の書き方、読んだ論文が支える内容だけを書き、mediaのlabelは論文で見たものだけ。新規調査は6段階目で統合した調査から書く。追加調査は頼まれたら書き直し、手法・課題・論文を変えたら該当する節と引用を更新する。チュートリアルの無い調査には、作る依頼を候補に出す。

## 階層と派生問題（2026-10-12、ユーザー指示「ToCと文章をmdの階層構造に。派生問題をもっと詳細に」）

- 目次と本文は、Markdownの見出しの階層のように番号つきで描く（`tutorialOutline`）。同じ役割が続く節は1つの章（見出しは役割名、例：3 解き方）になり、各節が 3.1・3.2… になる。1節だけの役割は、その節の見出しを章の見出しにする。本文中の「### 見出し」の行は小見出しとして描く。
- 派生問題は、派生問題1つに1節（基本の問題との違い・何が難しくなるか・対応する手法）。サンプルは6節：衝突の定義、目的関数、最適性の要求、lifelong MAPFとMAPD、部分観測・分散、倉庫のシナリオ。用語を整理した論文（Stern et al., SoCS 2019）の衝突の種類と倉庫のシナリオの図、PIBTのMAPDの図、各論文のアブストラクトの範囲で書いた。

章立てと採点表は [0038](0038-integrated-tutorial-style.md) で、MAPF見本・LLM Open Challenges・地図表現の研究動向の記事を統合した形に改めた（はじめにを先頭に、典型的な〇〇と研究動向「AからBへ」、まとめの方向性3つ。数式は必須でなくした）。上の採点表と下の基準の節は、0038の変更を除いて有効。

## 基準のチュートリアル（2026-10-12、ユーザー指示「このサンプルをチュートリアルの基準にして」）

- サンプルの「MAPFの入門（サンプル）」を基準にする（`packages/domain/src/tutorial-reference.ts`）。
- Prompt：tutorialの規則の末尾に、基準の章立て（章と節の見出しと役割）、規模（解き方・課題と達成度・派生問題の節の数、字数、図、引用した論文と主張、未解決の問い）、課題と達成度の節の例（形の手本。引用のIDは伏せる）を入れる。分野が小さければ節は少なくてよいが、役割と各節の中身の種類はそろえる。基準はサンプルから組み立てるので、サンプルを変えるとPromptも変わる（版を更新する）。
- 採点：派生問題を1つに1節で3節以上（`variants_sections`）を加えた。
- 比較：`npm run survey:assess` は、採点に加えて基準との比較（解き方・課題と達成度・派生問題の節、字数、図、引用した論文・主張、未解決の問いの、値・基準・割合）を出す。Labのチュートリアルの要件に基準の数値を出す。

## 画面

タブ「チュートリアル」（最初のタブ）。題、目次（役割と見出し）、節ごとに本文（段落・箇条書き・数式はKaTeX）、引用は短い表記（著者+ 会議 年）のボタンで、押すと右の詳細にその項目を出す。mediaはarXiv HTML版から図・アルゴリズム・数式を引いて表示（取得の規則は0016と同じ）。refsのうち本文で引用していないものは節の末尾に並べる。無ければ「チュートリアル未作成」。
